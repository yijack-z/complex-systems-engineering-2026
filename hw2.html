00 作业说明 / BRIEF

这份文档要回答什么

概念阶段不解决"怎么做"，只解决为什么做、为谁做、做到什么算成功。 因此本页不做详细设计，只产出两份需求规格：描述组织为什么启动项目的 BRS， 以及从相关方视角定义需求的 StRS。

依据的来源

框架取自《第4章 概念定义》中的表4-1（BRS）与表4-5（StRS），方法取自 4.1 业务或使命分析、4.2 相关方需要与需求定义。

两份文档的分工

BRS 站在业务管理层面，回答"组织为什么要变"；StRS 站在业务运行层面，回答"相关方要什么"。

本页的重点

业务/任务需求、ConOps 与 OpsCon 的区分、相关方清单、相关方需求条目，以及它们之间的冲突。

关于目录结构：下面第 01–03 节是 BRS 与两个"概念"的展开，第 04–05 节是相关方与 StRS， 第 06 节记录这一阶段真正要交出去的东西——冲突清单，它才是后续权衡研究的输入。

依据来源：[1] ISO/IEC/IEEE 29148:2018（需求工程过程标准，表4-1 与表4-5 的出处）； [2] ISO/IEC/IEEE 15288:2023（系统生存周期过程，业务或使命分析过程的活动划分）； [3] 郭宝柱等《系统工程——基于国际标准过程的研究与实践》第4章。条目见文末「参考资料」。

01 BRS 业务需求规格说明

业务需求规格说明

按表4-1 的八章轮廓展开，逐条给出本项目的内容。

1简介

1.1 业务目的

现存的洲际运输体系在速度、容量与能耗上已经接近天花板：航空受限于机场吞吐与碳约束， 海运受限于时效，陆路受限于地理。组织寻求一种地表尺度上的新运输骨干， 并希望这条骨干同时承担能源、科研与居住功能，把一次性的巨型投资摊到多种收益上。

1.2 业务范围

  • 业务域：洲际高速运输、沿线能源输配、科研实验平台、轨道延伸运输。
  • 范围内：干线环线与分支线的规划、建设、运营与维护；跨洲协调与标准制定。
  • 范围外：具体线位设计、车辆详细设计、单站建筑设计（属方案域，不在概念阶段）。

1.3 业务概况

业务由四张网叠加构成：运输网（干线 + 分支）、能源网（沿线发电与储能）、 科研网（长距离真空与超导实验）、管控网（调度、真空监测、应急隔离）。 四网共用同一条物理管廊，是这套业务能摊薄成本的根本原因。

1.4 定义

  • ConOps（运营概念）：组织层面，描述组织打算如何运作，涉及多个系统的组合。
  • OpsCon（运行概念）：系统层面，描述某个系统做什么、为什么，不涉及怎么做。
  • BRS / StRS：业务需求规格说明 / 相关方需求规格说明，分别对应组织层与运行层。
  • SoS（体系）：由多个可独立运行的系统组成的集合，整体呈现涌现能力。

1.5 主要相关方

七类相关方的完整清单与权力—利益分析见第 04 节，此处只列类别：主权政府与出资方、直接用户、运营维护方、监管与标准机构、受影响第三方、技术供应链、远期太空相关方。

3业务管理需求

3.1 业务环境

  • 技术环境：磁浮、真空、盾构、超导均有工程基础，但没有一次被放到万公里尺度。
  • 法规环境：真空压力容器、载人运输、跨境通关、海底施工与空间资产权责分属不同法域。
  • 地缘环境：环线必然穿越多国，线路与调度主权是首要谈判议题。
  • 生态环境：地表与海底扰动不可消除，只能控制与可逆化。
  • 经济环境：单公里造价为地铁量级以上，回收周期跨代。

3.2 使命、目的与目标

使命—目的—目标三层，附成功度量
层级内容成功度量
使命在地表尺度重建运输骨干，并把它作为后续空间开发的起跳结构骨干线贯通并稳定运营
目的把洲际行程压缩到小时级；为沿线与轨道提供可承载的结构端到端时间、结构承载力
目标一期示范段跑通真空+悬浮+气闸+隔离闸门；三期实现跨洲运营各期验证门限达成率

3.3 业务模型

采用大洲牵头制：各洲由一到两个牵头方负责本洲段的融资、建设与运营， 洲际设中转站完成换乘与海关；跨洲管委会掌握接口标准与联合调度。 收益来自四部分：旅游与客运票务、夜间货运、能源管廊租用、科研平台使用。

3.4 信息环境

  • 统一接口标准库（管径、真空度、供电制式、舱体接口、救援规范）。
  • 跨洲调度信息共享（时刻、真空状态、闸门状态、事故通报）。
  • 分段资产与维护记录（按管段编号追溯，用于寿命与责任划分）。

4业务运行需求

4.1 业务过程

  • 规划过程：选线、环评、跨境协定、分期立项。
  • 建设过程：盾构掘进、管节铺设、设备安装、分段验收。
  • 运营过程：客运（日间）、货运（夜间）、科研（预约窗口）。
  • 维护过程：天窗检修、闸门与泵组更换、管段复压。
  • 退役过程：管段封存或拆除、生态恢复。

4.2 业务运营策略与规则

  • 停站规则：大洲站每洲 1–2 座，站间距决定平均速度上限。
  • 时段规则：日间客运优先，夜间货运优先，科研占用预约窗口。
  • 隔离规则：单段失压立即封段，其余段维持运行，不整线停运。
  • 票价规则：观光段、通勤段、货运分档计价。

4.3 业务运行约束

  • 单公里造价与总投资上限（量级约束，非精确预算；口径见 [5]）。
  • 生态扰动不得超过环评设定的可逆阈值。
  • 不得单方面改变已互认的核心接口标准。
  • 运营安全指标须满足载人运输准入要求。

4.4 业务运行质量

  • 准点率、可用率、平均无故障里程作为一级运营指标。
  • 失效时"降级而非瘫痪"：任一段可独立隔离。
  • 救援响应时间按地下 / 海底 / 轨道三类场景分别设定。

4.5 业务结构

三层结构：跨洲管委会（标准与联合调度）→ 大洲运营商（本洲段建设与运营）→ 站点运营单元（站内服务与接驳）。

5提案系统初步运行概念

5.1 初步运行概念

系统以"环线 + 分支"的拓扑提供运输能力：干线管内维持真空，舱体悬浮运行； 车站以气闸与真空段隔离；管段之间设隔离闸门。系统同时对外提供管廊（能源）、 实验窗口（科研）与结构接口（后续轨道延伸）。

5.2 初步运行场景

  • 场景 A · 洲际客运：站内安检 → 气闸进舱 → 加速段 → 干线巡航 → 目标站减速 → 出站。
  • 场景 B · 夜间货运：集装箱装舱 → 低峰时段发车 → 直达货运站 → 分拨。
  • 场景 C · 科研窗口：预约时段停运客运 → 开放真空段 → 实验载荷进出 → 恢复运营。

6其他初步生存周期概念

  • 采办：按模块招标，管节、泵组、闸门、定子段分别定标。
  • 部署：分期建设，示范段→区域线→洲际线→环线。
  • 支持：沿线设维护基地，备件按模块化库存。
  • 弃置：管段可封存、可拆除，拆后恢复地表或海床。

7项目约束

  • 概念阶段周期与交付节点由课程安排约束（本期为 2026-11-18）。
  • 人力与算力有限，只能做定性论证与量级估算，不做精确仿真。
  • 资料可得性受限，部分数据取公开报道的约数。

02 ConOps 运营概念（组织层）

组织打算怎么用这套系统

ConOps 描述的是组织层面的运作意图，它面对的是"多个系统组成的组合"， 单个系统在其中只是一个黑盒。所以这一节不讨论管道怎么造，只讨论组织为什么要它、拿它做什么。

本项目的 ConOps

  • 目标：让跨洲流动变成常态化、可负担的日常行为，而不是少数人的远行。
  • 目的：以一条骨干线带动沿线与轨道两侧的产业和聚居，形成新的经济走廊。
  • 期望：运输、能源、科研、居住四类活动共用一条物理骨架，各自独立运营、共享标准。
  • 职责划分：牵头方管本洲段，管委会管接口与联调，监管方管准入与安全底线。
  • 运行与支持环境：地下、海底、极区、跨境；维护依赖沿线基地与模块化备件。
ConOps 与 OpsCon 的区别（本章 4.1.2 的核心辨析）
维度ConOps 运营概念OpsCon 运行概念
层次组织层（多系统组合）系统层（单个系统）
回答组织为什么这样运作系统做什么、为什么
关系多对多：体系内各系统交互一对多：以目标系统为核心对外交互
本项目对应四网叠加、大洲牵头、跨洲联调真空管道运输系统自身的运行场景

辨析依据：[3]《第4章 概念定义》4.1.2 节「ConOps 与 OpsCon 辨析」；标准定义见 [1]。

03 OpsCon 运行概念（系统层）

这个系统做什么、为什么

OpsCon 只描述"做什么"与"为什么"，不描述"怎么做"。它从用户视角给出系统的运行环境、 运行模式与关键场景，是后续功能需求与确认测试的来源。

运行环境

  • 物理环境：地下浅埋段、海底段、极区段；管内为真空，管外为地层或海水。
  • 接口环境：与既有铁路、航空、海运的接驳；与电网、氢网的能源接口。
  • 制度环境：跨境运行，需同时满足多国监管与统一标准。

运行模式与状态

系统运行模式（对应 BRS 4.4 与 StRS 4.4）
模式触发条件系统行为
正常运营真空度、闸门、供电均正常按时刻表发车，客运/货运/科研按窗口切换
降级运营单段真空度下降或设备故障封段、绕行或限速，其余段继续运行

权力—利益四象限

把七类相关方按权力（能不能否决或改变项目）与利益（受项目影响的深浅） 摆进四象限，可以看出这一阶段的发力点在哪。

读图说明：权力与利益都是相对判断，依据来自第 04 节的关切分析，不是量化评分； 同一类相关方内部也可能分裂（例如中央政府与地方政府立场不同），概念阶段先按类别归档。

05 StRS 相关方需求规格说明

相关方需求规格说明

按表4-5 的八章轮廓展开；第 5 章为用户需求条目，是本页的重点。

1简介

1.1 相关方目的

定义组织在什么条件下、以什么方式使用这套系统为业务带来价值；明确"谁的需求优先"。

1.2 相关方范围

覆盖地表干线、分支、车站、轨道接驳段；不覆盖具体车辆设计与站点建筑。

1.3 概况

系统以环线为骨干，串联大洲站；分支降速接入；竖直段作为远期入轨通道。

1.4 定义

术语同 BRS 1.4；另增"降级运营""隔离段""验证门限"三个本地定义。

1.5 相关方

见第 04 节七类清单。

2参考

3业务管理需求

3.1 业务环境

跨境、跨法域、跨气候带；技术基础存在但未经验证于超长尺度。

3.2 使命、目的与目标

使命：重建地表运输骨干并作为空间开发起跳结构。目的：洲际小时级、结构可承载。目标：分期验证门限。

3.3 业务模型

大洲牵头 + 跨洲管委会；收入来自票务、货运、管廊、科研四类。

3.4 信息环境

统一标准库、跨洲调度信息、分段资产台账。

4系统运行需求

4.1 系统过程

发车、巡航、进站、检修、应急隔离、复压六个主过程。

4.2 系统运行策略与规则

日间客运优先、夜间货运优先、科研预约；单段失压即封段。

4.3 系统运行约束

加速度上限（乘客舒适）、真空度维持能力、闸门启闭时间、救援可达时间。

4.4 系统运行模式与状态

正常 / 降级 / 隔离检修 / 应急 / 停运，见第 03 节表。

06 冲突与权衡 / TRADE-OFFS

这一阶段真正的产出：冲突清单

相关方分析的价值不在"列全了谁"，而在把互相打架的诉求摊开。 下面四组冲突，是后续顶层目标与权衡研究的直接输入。

概念阶段识别的四组主要冲突
冲突一方另一方权衡方向
闸门密度出资方：闸门越多越贵，希望减少救援方：隔离越细越安全，希望加密按"单段最大可接受损失"反推间距
站距与速度沿线城市：希望设站带动经济干线乘客：希望少停站保速度大站少设，支线接入，分层服务
主权与统一各国政府：要线路与调度主权管委会：要统一接口与联调核心标准统一，洲内事务自治
造价与生态投资方：控制造价环保方：要求可逆与低扰动选线避让优先于事后补偿

一句话总结：概念阶段的相关方分析，目的不是敲定方案，而是把"出资方想省闸门、 救援方想加密闸门""货运想优先、客运想准点""地表国家关心主权、太空段涉及外层空间法规" 这些矛盾记录下来，作为后续权衡研究的输入。
